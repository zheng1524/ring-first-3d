## 3. 配准和多参考深度偏差

`surface_fusion_v2`的Ring配准不是息肉Mesh ICP：固定torus尺寸，以soft-L1拟合2倾斜＋3平移，yaw固定，边界±10°/±2mm。3次合成Ring留出点MAE约0.26/0.19/0.27→0.11mm，但留出Ring IoU均下降，相机ATE分别0→0.701、0.345→1.479、0.145→1.066mm；3次均未通过整体场景校正验证。真实0/1候选未过门槛，H=I仅用于SKIPPED显示，不能算配准成功。

后来的置信融合仍在固定相机下使用原多参考深度：004 ref03→08有符号中位−0.764mm、反向+0.836mm；005 raw57→459为−0.786mm、反向+0.627mm。完整12个有向配对和长尾均见[冲突表](metrics/multireference_conflicts.csv)。深度差包含视图遮挡和可能不同物理表面，不能逐点自动认作错误或唯一归因HERO/相机，但足以说明原位焊接和拓扑切分未消除成片不一致。

## 4. 哪些模块可复用，哪些不宜沿用

| 判定 | 原模块/函数 | 使用边界 |
| --- | --- | --- |
| 可直接复用基础接口 | `filters.py::raw_points/original_mesh`，原深度和像素身份；torus raycasting适配 | 保持mm、轴向Z、c2w、原Mask及面来源；不因坐标换算宣称精度增益 |
| 可复用诊断 | `diagnose`、`multiview`的事件/残差；`topology`、`map_faces`、误删评价 | 保留UNKNOWN和全部失败分母；相关HERO预测不算独立真值 |
| 有限复用整理 | `conservative_topology` | 不变几何、可追溯拆顶点；004仍残余1条非流形边，会碎裂，不能修形 |
| 仅保留实验性/失败对照 | SOR/ROR、P3删除、P4禁面、C的`merge_supported/remap_faces`、TSDF替代 | 有误删、错误拓扑或薄结构损失；不能直接升级默认主线 |
| 仅评价 | `evaluate_gt.py::oracle/gt_eval` | GT辅助ICP禁止进入预测配准、主面选择或正式融合 |
| 未通过 | Ring点云全局配准、跨视频Full-LightGlue/Full-RoMa组合 | 前者合成独立验证失败；后者仍UNVERIFIED分层，不能当可信联合Mesh |

绝对路径、函数行号、逐文件SHA及用途见[30函数模块清单](metrics/reusable_modules.csv)。没有复制算法代码或第三方依赖。

这里“可复用”指已有算法与数据接口：执行时仍依赖旧环境、`icf_common/pc_common/vnext_common`及只读源路径，不表示它们已成为新仓库内独立可安装的软件包。

**与新主面驱动方案真正不同的部分**是：历史没有独立可信主面的选择与冻结；没有以该固定主面为目标，对其他来源表面执行有界位姿/深度优化；没有在独立验证后再接受附加表面的流程。已有C是多源对称平均，B1是几何不动的拓扑整理，Ring H是整个场景一起移动，Oracle ICP是评分工具。这些不能作为新方案已被历史成功验证的证据。本轮只指出差异，不实现新方案或以GT预选主面。
