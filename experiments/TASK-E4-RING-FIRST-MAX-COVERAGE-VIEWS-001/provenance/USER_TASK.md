# 四、任务B：最大覆盖视角选择

这是本轮的第二个核心任务。

## B1. 不再以固定数量作为唯一目标

首先建立全部有效候选集合：

\[
\mathcal C=\{c_1,\ldots,c_N\}
\]

每个候选包含：

- 公制相机；
- RGB与Mask；
- 真实拍摄来源；
- 相机质量；
- 方向；
- 已知或估计的可见表面；
- RGB匹配支持；
- 潜在HERO目标资格。

**必须先覆盖尽可能多的有效观察方向，再决定需要多少帧。**

不允许通过重复选择几乎相同的视角凑齐36张。

## B2. 优先最大化真实可见表面覆盖

对候选相机 \(c_i\)，根据冻结的HERO和粗Body代理估计可见区域：

\[
\mathcal V_i
\]

当前已选集合 \(S\) 的覆盖：

\[
A(S)=
A\left(\bigcup_{i\in S}\mathcal V_i\right)
\]

新增候选的边际覆盖：

\[
\boxed{
\Delta A_i=A(S\cup\{i\})-A(S)
}
\]

采用成熟的贪心最大覆盖算法，或可复用的等价子模优化实现。

注意：

- Body只可作为粗几何代理；
- 不得将Body缺失区域当作真实不存在；
- 特别保护现有HERO已经证明存在的长柄、连接和基底结构；
- 不同来源的高度相关观测不能重复计算为独立可见面积；
- 未知背面不得凭空计入已恢复面积。

对于多个候选新增面积相近的情况，再考虑：

1. 相机配准可靠性；
2. 有效视差；
3. 图像清晰度；
4. 反光；
5. Polyp有效像素；
6. Ring遮挡；
7. 与现有视角的冗余程度。

不允许为了追求大角度而选择根本无法可靠恢复深度的视角。

## B3. 使用两层覆盖指标

为了避免被现有Body不完整性误导，必须同时统计：

**第一层：观察方向覆盖。**

包括：

- 相机球面方向分布；
- 最大与中位方向夹角；
- 球面分区占据率；
- 方向冗余；
- 有效视差分布。

**第二层：真实几何代理覆盖。**

包括：

- 现有HERO可见曲面的累计覆盖；
- Body代理表面可见范围；
- 单来源观察区域；
- 两个及以上有效独立方向支持的区域；
- 三个及以上有效独立方向支持的区域；
- UNKNOWN区域。

二者必须独立汇报。

不要把角度跨度直接称为真实表面覆盖率。

## B4. 优先解决G03

G03目前已登记9个视频视角的最大方向夹角约17.5°。

本轮优先回答：

1. 原始video004是否存在遗漏的大角度观察？
2. video005是否存在互补视角？
3. 三张独立照片是否观察到不同侧面？
4. 哪些视角能真正增加头部、柄部、连接区域的可见面积？
5. 如果所有原始数据都集中于一侧，新增36张是否仍然没有明显收益？

上述问题必须给出实际相机分布和真实RGB证据。

不能只给结论。

四组使用相同选帧方法，不开发G03专用算法。

# 十二、执行阶段与停止规则

## Stage A：数据发现与坐标审计

完成所有来源清点、身份验证和候选池建设。

如果缺少某段视频或照片，记录准确缺失原因，继续其他来源。

不能因为单个来源失败就暂停整个四组研究。

## Stage B：公制配准

优先运行Ring-First＋真实RGB配准。

完成两视频及照片的数值相机恢复和独立质量分级。

严重物理错误的相机不得进入正式重建。

弱验证候选可以保留用于探索性方向分析。

## Stage C：最大覆盖选帧

利用所有已审计候选建立相机分布和覆盖模型。

运行数量消融。

必须明确给出每组实际推荐的目标视角数及原因。

如果没有新的观察方向，不能继续强制增加相似帧。

## Stage D：新增HERO实际推理

在真实可用GPU和已验证相机条件下，尽可能完成新增目标的官方HERO推理。

如果部分目标失败，保留成功来源和失败日志。

不得用旧HERO重投影补齐缺失推理数量。

## Stage E：覆盖与独立几何评价

冻结结果后完成所有覆盖分析和真实HERO比较。

本轮不自动进入Body训练。

# 十四、研究纪律

本轮禁止：

1. 修改Ring-First物理建模。
2. 修改Ring尺寸、截面厚度或坐标规范。
3. 修改DXY主线。
4. 使用GT选择相机和视角。
5. 将Body作为相机恢复的监督真值。
6. 利用HERO强行修正公制相机。
7. 把数值位姿冒充已认证相机。
8. 为达到36张而保留大量重复方向。
9. 在没有真实配准的情况下强行合并视频。
10. 修改原生HERO深度或原始Mesh。
11. 通过ICP或非刚性调整制造覆盖改善。
12. 更新Body或执行曲面融合。
13. 使用HOLDOUT RGB/Mask/HERO参与正式FIT深度生成或形状更新；如重新划分数据，必须预先冻结，并公开历史初始化可能存在的数据依赖。
14. 为单独息肉形态设计特殊算法补丁。

所有算法对G01/G03/G05/G06采用统一规则。
