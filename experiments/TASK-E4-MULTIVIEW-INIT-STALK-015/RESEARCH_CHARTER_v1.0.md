# 息肉主体重建研究任务章程
**版本：v1.0｜日期：2026-11-09**  
**项目：Reference-Ring Anchored Visible-Surface Reconstruction of Polyps**  
**主仓库：`zheng1524/ring-first-3d`**

> 本文件是主体重建方向的长期任务与当前短期任务的共同依据。Codex、PM、RA 及独立辅助智能体开始工作前，应先阅读本文件及仓库中对应实验的最新技术报告。本文是可持续更新的研究章程，不替代代码、实验配置和原始证据。

## 1. 长期研究目标

建立一套**几何优先、证据感知、主体引导**的息肉三维重建系统，将不同来源、不同可信度的几何信息组织为统一模型。

### 1.1 已有资产及其职责

| 资产 | 当前价值 | 长期职责 |
|---|---|---|
| Ring-First | Ring 提供公制尺度和相机几何锚点 | 固定公制参考；按验证等级向下游提供相机 |
| 原生 HERO Mesh / Depth | 局部几何质量和真实纹理信息较好，但存在边缘噪声、帧间错位及深度冲突 | 可信局部表面观测，尽可能保留原始几何与来源身份 |
| PyTorch3D 主体 Mesh | 能表达整体形态并补充未观测区域，但部分组存在形态、尺寸和 Ip 柄部问题 | 整体几何骨架及未观测区域的形状先验 |
| 多视频、多关键帧 | 提供互补轮廓、观察方向及局部表面信息 | 按证据资格提供轮廓、主体拟合或 HERO 三维补片 |
| Blender / 虚拟息肉环境 | 已知模型与相机轨迹，可构造受控观测 | 定位初始化、可见性、相机、Mask、深度及更新机制的问题 |

### 1.2 最终模型的组成

长期目标不是无差别融合点云或 Mesh，而是构建具有几何来源标签的统一模型：

\[
M_{\mathrm{final}}=H_{\mathrm{trusted}}\cup T_{\mathrm{transition}}\cup B_{\mathrm{prior}}
\]

- `H_trusted`：通过质量与可见性检查的 HERO 原生局部表面，核心区域尽可能保留。
- `T_transition`：HERO 与主体之间的连接/过渡区域，明确标记为推断几何。
- `B_prior`：主体模型补充的未观测区域，明确标记为先验推断。

必要时保留两种输出：
1. **Observed Reconstruction**：只包含真实观测及有充分支持的表面，可以不完整。
2. **Prior-assisted Reconstruction**：在前者基础上加入过渡面和主体先验，形成更完整的模型。

### 1.3 长期研究主线

1. 主体模型：整体形态、尺寸、方向、基底及 Ip 头柄结构。
2. HERO 证据组织：可信面片、弱边界、遮挡/Unknown、跨帧冲突。
3. 主体—HERO 对应：判断是否为同一物理表面，而非仅凭欧氏最近距离。
4. 选择性融合：保留可信 HERO，局部适配主体，建立过渡带。
5. 跨视频统一：先验证相机和共享主体约束，再逐步允许 HERO 面片跨视频融合。
6. 纹理恢复：几何稳定后，将真实 RGB 投影到可信可见表面。
7. 可信度与测量：区分观测、共同支持、过渡和先验区域，分析测量对相机/深度/形状先验的敏感性。

## 2. 不可违反的研究边界

1. **Ring CAD、公制尺度和已冻结的 Ring-First 坐标定义不得为降低息肉误差而任意改变。**
2. GT 仅用于独立评价，不得参与初始化、训练、拟合、超参数选择或失败组修补。若某实验需要 GT 参与，必须先单独提出并获得明确批准。
3. DXY 测量主线只读；不得修改 DXY 算法或把三维重建实验结果写回 DXY 主线。
4. HERO 原始 Mesh、Raw XYZ、相机、RGB/Mask、Ring CAD 和原始 face identity 必须可追溯。不得用历史融合 Mesh 或预测表面静默替代原生 HERO 输入。
5. Unknown、遮挡、无效深度和开放边界不得被解释为零深度、自由空间或已知 inside/outside。
6. 不得对完整主体与开放 HERO 使用不加区分的双向 Chamfer；不得把未观测背面强行拉向 HERO 前表面。
7. 不得同时无约束地优化所有相机、HERO 深度、主体参数和全部 Mesh 顶点。
8. 不得为某一类型（例如 Ip）设计破坏其他类型通用性的全局特例。允许在共享框架下使用有明确几何意义的形态分支。
9. 不得静默替换实验算法、损失项、输入视角、GT 使用方式或验收口径。若无法按设计实现，先报告差异与备选方案，等待确认。
10. 所有失败组均需保留结果和失败原因，不得静默跳过或只报告成功样例。

## 3. 当前短期任务：主体拟合优化轮次

**总体目标：Multi-view Initialization Refinement + Ip Stalk-aware Mesh Optimization**

本轮分两个阶段，按顺序执行。第一阶段覆盖所有纳入实验的输入组；第二阶段只对 Ip 进行柄部专项更新。Is、IIa 在本轮只参与初始化与统一主体优化，不做额外的局部结构更新。

### Phase A：所有输入组的初始化优化

#### A1. 数据与代码审计

先从仓库当前实验清单确定“所有输入组”的权威范围，不得自行挑选少数容易成功的组。核对：
- 每组可用 RGB、Mask、相机、Ring、HERO 原生深度和 GT；
- GT 是否与当前公制坐标、物体身份和版本匹配；
- 当前初始化生成方式、使用视角、形状参数、网格拓扑；
- 下游优化损失、权重、迭代设置及局部更新机制。

缺少某类数据时明确标记，不得把 RGB/Mask 视角冒充 HERO 深度视角。

#### A2. 初始化对照

至少比较以下三种方案：

| 方案 | 定义 | 目的 |
|---|---|---|
| Init-A | 当前初始化流程，作为冻结基线 | 测量现有方法表现 |
| Init-B | 同一视频内多个互补视角共同初始化 | 检验视角互补对初始几何的贡献 |
| Init-C | 形态参数化先验生成初始形状，再由多视角轮廓修正 | 检验更合理的形态先验是否改善初始化 |

要求：
- 视角选择依据清晰度、轮廓完整性、观察方向互补性、Ring 遮挡和结构可见性，不以帧数堆叠代替几何互补。
- 为公平比较，尽量固定三种初始化之后的下游优化器、损失和参数；若确实无法固定，明确列出差异。
- 为所有组输出三种初始化及其统一优化后的结果；失败也要输出诊断。
- 保留独立留出视角，不得用全部视角拟合后再把训练误差当作泛化证据。
- GT 只在拟合结束后运行独立评价。

#### A3. 评价

每组至少报告：
- 初始化前/后及优化后的 GT 几何指标（数据可用时）；
- Chamfer Distance、F-score（明确距离阈值、采样方式和单位）；
- 关键尺寸误差；
- 多视角轮廓误差；
- 不同初始化/视角子集下的形态稳定性；
- 训练视角与留出视角表现。

GT 评价必须在统一公制坐标中进行。不得为每个预测结果单独做尺度或刚性 ICP 对齐后再报告主要精度；如提供对齐后指标，只能作为补充诊断，并同时报告未对齐指标。

### Phase B：Ip 柄部更新专项

仅在 Phase A 的初始化主线确定后开展。Is、IIa 不进入本阶段局部更新。

#### B1. 先诊断当前更新机制

重点检查 013/014：
- 柄部相关顶点是否进入候选更新集合；
- 候选集合覆盖率、实际更新率和顶点位移；
- 柄部各损失项的梯度分布；
- Ring 约束拒绝哪些更新、拒绝原因是什么；
- 形状正则是否阻碍真实柄部延伸；
- 网格分辨率/拓扑是否足以表达柄部；
- 轮廓残差如何映射到三维柄部顶点。

已知历史诊断提示：014 G03 的远轮廓代理涉及 239 个顶点，但四个局部候选带仅覆盖 30 个，且 Ring 约束拒绝了大量候选更新。必须重新核对当前代码和数据，不得仅复述历史数字作为新实验结论。

#### B2. 柄部更新对照

| 方案 | 定义 | 目的 |
|---|---|---|
| Stalk-A | 当前自由顶点更新 | 基线 |
| Stalk-B | 修正候选带/更新覆盖与梯度传递；保留有效 Ring 几何约束 | 检验更新覆盖是否是瓶颈 |
| Stalk-C | 柄部中心线与变截面参数化 + 局部自由顶点残差 | 检验显式柄部表达是否更有效 |

参数化柄部至少表达中心线、长度/方向、沿线截面半径及头柄连接区域。不得通过简单取消 Ring 约束换取表面改善；应区分真实几何约束、Ring 遮挡/未知区域和不相关顶点。

对 Ip 报告头部、柄部、头柄连接区域的独立指标，包括几何距离、柄部长度、中心线方向、截面半径和留出轮廓。若 GT 无法可靠分割头/柄区域，明确标注评价限制。

### Phase C：必要时进行虚拟环境诊断

当真实数据无法区分初始化、可见性、相机、Mask、HERO 深度和更新机制的影响时，使用已有虚拟息肉环境开展受控实验，不要无必要地扩大仿真任务。

优先：
1. **初始化验证**：已知 GT 和相机轨迹下比较不同初始化。
2. **柄部可见性消融**：逐步改变柄部可见程度，观察可恢复性。
3. **受控扰动**：分别扰动相机、Mask 边界、HERO 深度、初始柄长/方向，测量柄部误差变化。

仿真用于定位机制与验证因果，不替代真实硅胶息肉验证。

## 4. 本轮结束条件：B0 主体适配资格

主体无需先成为完美的完整息肉模型。达到以下条件即可进入单视频 HERO—主体适配：

- Ring 公制尺度和坐标定义固定，无明显坐标/单位错误；
- 主体中心、整体方向、主要尺寸和基本形态合理；
- 主要训练视角及独立留出视角的轮廓能够得到合理解释；
- 不同合理初始化下主体整体结构基本稳定；
- 无严重自交、翻面、异常薄片或拓扑错误；
- 能够定位 HERO 面片大致对应主体的区域；
- 未观测背面允许是粗略先验，不要求达到真实表面精度；
- Ip 至少具有合理头部、柄部连接位置和柄部空间延伸，不要求柄部每个局部细节都由主体独立恢复。

**Is/IIa：** 若整体形态、尺寸、轮廓和稳定性已足够，不再继续增加局部更新复杂度。  
**Ip：** 若柄部仍有误差，但 HERO 能提供可靠局部表面，且主体具备合理的整体柄部骨架，可以进入适配；若主体柄部结构完全错误且会妨碍对应/补全，则继续修正。

B0 不是物理测量认证。跨视频统一和定量测量仍需各自独立验收。

## 5. 每次 Codex 任务必须交付的技术报告摘要

每次实验/任务完成后，必须新增或更新一份简洁的 `TECHNICAL_REPORT_SUMMARY.md`（每个独立实验目录内），不能只写“完成”或只展示图片。

摘要至少包含：

1. **任务与版本**：实验 ID、分支/commit、运行配置、输入数据范围。
2. **原定算法合同**：本任务计划实现的步骤、公式/损失、视角和约束。
3. **实际实现对照**：逐项列出“原定设计 → 实际代码实现 → 代码位置/函数 → 是否一致”。
4. **数据覆盖**：计划组数、实际完成组数、失败/缺失组及原因。
5. **结果**：核心指标表、代表性可视化、GT 是否仅用于评价。
6. **失败分析**：区分数据、初始化、表达能力、优化、约束和实现偏差。
7. **偏离与限制**：任何算法替换、简化、未实现项、临时参数和未验证假设，必须显式披露。
8. **结论与决策**：哪些假设得到支持/否定，是否达到 B0，建议下一步。
9. **复现信息**：运行命令、配置文件、关键产物路径。

若实际实现与设计不一致，必须明确写出差异及其对结果的影响。不得将“实现了一个近似版本”描述为“完成原算法”。若设计无法忠实实现，应暂停该部分并提出差异说明及替代方案，不能静默替换。

## 6. 辅助智能体协作规则

本文件用于让独立智能体快速接管明确子任务。可按需启动：

- **Initialization RA**：只研究多视角初始化、视角互补和初始化稳定性。
- **Ip Stalk RA**：只研究 Ip 柄部表达、候选顶点覆盖、梯度和局部更新。
- **GT Evaluation RA**：审计 GT 坐标、分割、采样与评价指标；不得参与拟合。
- **Simulation RA**：设计最小化虚拟实验，定位可见性/相机/深度/Mask 对柄部恢复的影响。
- **Integration PM**：维护主实验、执行顺序、结果比较和 B0 决策。

协作要求：
1. 每个辅助智能体先阅读本文件、对应实验代码和最新技术报告摘要。
2. 任务边界外只提出建议，不直接修改其他模块。
3. 避免多个智能体同时修改同一代码路径；先由 PM 分配文件/分支所有权。
4. 结论必须区分代码事实、实验观察、解释假设和建议。
5. 不允许仅凭单个成功案例宣称方法普遍有效。

## 7. 本文件的更新规则

本文件是长期任务章程，可以随研究进展更新，但不得被一次实验结果随意改写。

允许更新：
- 当前短期任务状态与下一阶段目标；
- 已通过/未通过的验收条件；
- 已被实验支持或否定的算法假设；
- 新增数据资产、模块职责和辅助智能体任务边界。

更新要求：
1. 修改前保留原版本或在 Git 中形成可追溯 diff。
2. 更新时增加版本号、日期和简短变更记录。
3. 不得删除失败证据或把未验证假设改写成事实。
4. 对长期目标、冻结边界或验收标准的实质性改变，先提交建议并等待人工确认。
5. 每次任务结束时，只在确有证据支持时更新本文件；实验细节仍写入对应技术报告，不把本文件变成冗长实验日志。
