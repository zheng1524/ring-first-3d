# 五、阶段 B：参考视频锚定与系统位姿修正

这是本轮的重要新研究环节。

## B1. 主视频选择

每个测量组优先选定一个主视频 A。

主视频评分可以考虑：

- 观察方向覆盖范围；
- 息肉轮廓完整程度；
- 高质量参考帧数量；
- 相机位姿稳定性；
- Ring 重投影；
- 背景纹理及可匹配程度。

不得根据 Blender GT 选择主视频。

G01 初步指定：

A = G01-video004
B = G01-video005

原因：

004 具有更丰富的观察方向和形态细节。

但需要特别强调：

G01-005 不被期待提供明显的新观察方向。

G01 的跨视频实验目标主要是：

STABILITY / SYSTEMATIC_BIAS / REPEATABILITY

而不是新增息肉可见面积。

必须将这三个指标与 NEW_COVERAGE 分开。

## B2. 视频共享刚性修正

对于视频 v：

T_corrected(v,i) = Delta_T(v) @ T_original(v,i)

其中：

Delta_T(v) 属于 SE(3)。

主视频 A：

Delta_T(A) = Identity

其他视频 B：

首先只允许学习一个视频级 6DoF 修正。

不得一开始就让每帧分别进行自由 6DoF 优化。

不允许额外引入尺度变化。

不允许更改原始相机资产。

派生修正和原始相机必须并行保留。

## B3. 相机修正依据

优先考虑：

1. Ring CAD 物理几何。
2. 静态背景特征对应。
3. Ring-First 原始位姿先验。
4. 现有历史 PnP/MASt3R/SIFT 匹配缓存。
5. 成熟稳健位姿优化。

优先复用成熟模块：

OpenCV PnP-RANSAC
SciPy least_squares
GTSAM 或 Ceres

只有现有实现不足时才增加新依赖。

禁止把 HERO 息肉表面的跨视频深度差
作为直接相机修正目标。

禁止简单使用多视角点云 ICP
把两个系统误差不明的 HERO 表面强行拉近。

第一阶段相机修正时：

冻结息肉 Mesh。

尽量使用 Ring 和静态背景证据。

不要直接以当前息肉轮廓不一致，
作为允许相机任意移动的理由。

## B4. 必须研究可辨识性

Ring 具有旋转对称性。

仅凭 Ring 未必能够唯一确定
绕 Ring 法向的旋转关系。

如果背景对应不足，
必须明确报告剩余旋转自由度的不确定性。

不允许将优化器得到的一个数值解
直接宣称为真实位姿。

必要时允许多个合理初始化候选，
但必须使用独立投影证据比较稳定性。

## B5. G01 稳定性实验

至少进行：

B0：完全不进行视频间修正。
B1：只修正视频 B 的共享 SE(3)。
B2：在严格先验下进行少量交替位姿/几何优化。

其中 B2 只有在 B1 有充分证据时执行。

增加一个重要负对照：

将 G01-video004 分为两个时间子集，
暂时视为 A1/A2。

因为二者属于同一视频轨迹，
理论上不需要较大的系统位姿修正。

观察算法是否错误地产生了明显的 Delta_T。

这可以检验相机修正模块
是否存在过拟合或不必要的自由漂移。

此外：

004→005 与 005→004 的投影检查都要保留。

不要只报告对某一方向有利的结果。

NO_GRADIENT
NO_ADMISSION_GATE
NO_STOP_CONDITION

# 七、阶段 D：轮廓损失与更新策略

## D1. 分别研究漏覆盖与错误越界

现有 013 已经证明：

G02：
减少漏覆盖的同时，
错误越界可能显著增加。

G03：
远轮廓漏覆盖仍然存在，
当前 Mesh 更新不足以恢复完整长柄。

因此应使用统一损失框架：

L_2D =
    lambda_FN * L_missing
  + lambda_FP * L_extra
  + lambda_boundary * L_contour

其中：

L_missing：
真实息肉像素没有被预测覆盖。

L_extra：
预测表面错误进入真实息肉之外的已知背景。

L_contour：
预测轮廓与真实轮廓的空间距离。

要求三个损失分量分别报告。

考虑：

- Soft IoU 或 Tversky；
- 双向轮廓距离；
- 有符号轮廓距离场；
- Ring 遮挡区域的已知/未知划分；
- 低可信 Mask 交界处软权重；
- 多视角归一化。

不允许只增加面积完整性损失，
而忽视错误越界。

## D2. 必须进行独立消融

保持视角集合一致。

D0：013 原始损失。
D1：正负区域分离归一化。
D2：增加双向轮廓距离。
D3：完整组合。

避免大范围盲目搜索超参数。

可以预先设定少量合理参数，
根据 FIT 结果选择用于后续验证的候选。

不得使用 HOLDOUT 或 Blender GT
挑选最优损失权重。

## D3. 不允许案例特化

不能因为 G03 是 Ip 就设计特定柄部损失。

可以使用：

- 通用远轮廓残差；
- 通用局部形变约束；
- 通用表面连续性；
- 通用可信 Mask 覆盖。

# 八、阶段 E：自适应 Mesh 细分

本轮批准正式尝试自适应细分。

但必须保留无细分对照。

## E1. 触发信号

优先考虑：

1. 多视角共同支持的高轮廓残差；
2. 局部边长显著拉伸；
3. 局部三角面异常变形；
4. 需要更多顶点表达的曲率变化。

细分不依赖息肉类型标签。

不得人工指定 G03 柄部独有的特殊细分算法。

## E2. 复用成熟实现

优先研究：

PyTorch3D SubdivideMeshes

用于验证全局增加网格分辨率的影响。

进一步研究：

Blender BMesh subdivide_edges

用于局部细分。

允许进行必要的最小适配，
但不得重新开发复杂 Mesh 重建框架。

## E3. 三组对照

E0：不细分，继续优化。

E1：全局统一细分一次，再优化。

E2：按轮廓残差与局部拉伸进行自适应细分，
    再优化。

要求：

细分操作本身不改变当前几何形状。

新顶点从原三角面插值得到。

新几何必须由后续真实投影损失驱动。

不得以细分名义直接补出柄部。

不得使用 GT 决定细分位置。

细分后重新建立必要的优化器状态，
并检查网格损失归一化是否变化。

## E4. G03 重点证据

必须可视化：

- 细分前 Mesh；
- 高残差区域；
- 高拉伸三角面；
- 实际被细分的面；
- 细分后未继续训练的 Mesh；
- 继续训练后的 Mesh。

要求统计：

- 顶点数量；
- 三角面数量；
- 细分区域数量；
- 最大边长拉伸比例；
- 长柄方向的几何延伸；
- 更新区域面积；
- Ring 碰撞变化；
- 非邻接自交情况。

不能仅通过顶点数量增加，
宣布表达能力问题已解决。

## E5. 几何可行性

013 已发现稀疏 Ring 检查可能遗漏
三角面内部穿透。

本轮必须修正这一问题。

至少采用足够密集的三角面检查，
并结合成熟的三角网格碰撞检测。

需要记录：

- 原模型已有的碰撞；
- 新增的碰撞；
- 最大材料穿透深度；
- 三角面退化；
- 非流形结构；
- 自交。

不能通过删除正确可见表面
降低损失或碰撞指标。

已有小量碰撞应记录，
但不允许新方法造成未报告的显著恶化。

# 九、统一 Blender GT 评价

保持之前批准的评价路线。

从最终场景中单独提取息肉。

Ring 和背景不参与息肉最佳刚性配准。

先使用 Ring 已知真实尺寸确定公制尺度。

随后：

禁止模型缩放；
禁止非刚性 GT 对齐；
禁止镜像。

只允许完整六自由度 SE(3) 刚性对齐。

输出：

Best 6-DoF Rigid Alignment

并明确说明这不是端到端相机定位精度。

每个模型的所有几何指标
必须使用同一个刚性对齐变换。

- 双向 Chamfer；
- GT→预测和预测→GT分向误差；
- Dxy；
- 高度或可靠的高度跨度；
- 条件满足时的实体 3D IoU；
- 可见表面覆盖；
- 缺失区域空间分布。

Ip 可额外报告柄部恢复诊断，
但不得为该指标单独训练专用模型。

对没有可靠基底的病例，
高度或体积指标保持 NOT_EVALUABLE，
不允许捏造基底平面。

不得以 P0 为 GT。

# 十四、最重要的执行原则

本轮不是一次简单的调参竞赛。

不要在 G02/G03 上进行大量权重搜索，
直到得到漂亮的二维图。

也不要因为某种相机修正能降低息肉 Mask 误差，
就认为它恢复了真实相机位姿。

必须通过 Ring、背景、
独立视角和三维几何共同分析。

不要重新引入跨视频 HERO 深度强制一致性。

不要因为某些相机存在旧的 UNQUALIFIED 标签，
就自动拒绝研究。

不要对 Ip/Is/IIa 设计三套不同算法。

不要以更多视角、更多顶点、
更长训练时间或更平滑的 Mesh
直接代表真实精度提升。

本轮真正的成功标准是：

1. 建立可复用的全测量组视角组织流程。
2. 形成可验证的视频级相机修正方法。
3. 明确新增视角对二维/三维误差的作用。
4. 明确轮廓损失改进的实际收益与副作用。
5. 明确局部细分是否解决形变瓶颈。
6. 得到可与 Blender 严谨比较的统一模型。
7. 为下一轮正式算法设计提供充分的正反证据。

如果最终改进有限，
但我们能够明确证明哪个环节失效、
为什么失效、下一步该修改哪里，

本轮仍然是有价值的科研实验。

请先完成历史代码复用和实验方案的简短审阅，
随后直接开展实际实验。

实验过程中按阶段保存结果，
最后统一提交完整报告、关键可视化、
运行命令、commit SHA 及主要结论。

不要只提交计划，不运行实验。
