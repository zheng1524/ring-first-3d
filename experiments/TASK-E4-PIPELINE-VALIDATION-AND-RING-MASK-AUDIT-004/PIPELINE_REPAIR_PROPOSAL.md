# PIPELINE_REPAIR_PROPOSAL

**STATUS: `AWAITING_RA_REVIEW`** · 本轮不实施。所有条目均需 RA 批准后才进入执行任务。

排序依据：**证据强度 × 预期收益 × 工程风险 × 对下游的影响**。三处优先修改见 §3。

---

## 1. 总原则

1. 优先"恢复被删掉的诊断"，而不是"新造算法"。本轮全部三项都是**已有证据的工程化**，没有一项需要新求解器。
2. 任何会改变"哪些实例产出预测"的改动，都必须单独立项、单独批准。
3. 不得用 GT 或 HOLDOUT 做任何选择、分支或阈值标定。允许使用 **FIT 掩膜**与**冻结输入资产**（EXACT013 Body）做诊断。
4. 不得放宽现有 3 px / 工程门限来"提高通过率"。

## 3. 三处优先修改（Q3 的直接回答）

### 修改 1（P1）：恢复 held-out 逐帧验证与旋转离散

| 项 | 内容 |
|---|---|
| **修改原因** | 002 删掉了 V6 的 `validate_select`，导致"标定版本选错"与"逐视角重解恶化"都无法被发现。本轮复算显示：G03/005 最终相机 held MAE **159.2 px**，是 BA v1（5.50）的 29 倍，却全程无任何告警。 |
| **具体文件/函数** | 新增 `experiments/.../code/validate.py`；在 `standard.py` 的 `banks` 阶段之后、`cameras` 之前调用；结果写入 `reference_build/REV*/metrics/CALIBRATION_VALIDATION.json` 与实例级 `CAMERA_VALIDATION.json` |
| **预计改动** | ~150 行新代码；**不改** `bootstrap_references.py` 的求解逻辑，只在 `build_one()` 末尾追加一次只读计算；不改 `cameras.py` 的相机选择 |
| **算法复用** | 直接复用 V6 `validate_select.py` 的**结构与阈值参数名**；`tracks005.npz` 的 `held` 已由冻结的 `track005.py` 生成，无需重算跟踪 |
| **是否改科学预测** | **否**（纯诊断输出） |
| **验证方式** | ① 用 V6 冻结相机重放，必须复现 `15/22` 与 `0/22`（本审计已验证可实现）；② 对 4 个 MATURE 实例输出 held MAE 表；③ 断言不写入任何 `ADMISSION.json` |
| **成功判据** | 复现 V6 计数；G03/005 的 `159.2 vs 5.50` 被检出并标 `SUSPECT` |
| **失败/回退** | 若 held 轨迹不足（如 G06 仅 18 条），输出 `INSUFFICIENT_EVIDENCE` 而非失败；回退 = 删除该调用，零副作用 |

**必须同时补的字段：** `initialization_rotation_spread_deg`（V6 有、002 删了；本数据 165°–176°）。

### 修改 2（P1）：相机-主体规范一致性诊断

| 项 | 内容 |
|---|---|
| **修改原因** | G03/005 的 Ring MAE 只有 0.6–1.1 px（全通过），但 INITIAL Body 投影 IoU 只有 0.229–0.304；同一批相机换成 v1 则是 0.842。Ring 的旋转对称性使 3 px 门限**原理上**看不到该失效。 |
| **具体文件/函数** | 新增 `code/gauge.py`；在 `standard.py` 的 `cameras` 阶段之后调用；输出 `runs/.../GAUGE_DIAGNOSTIC.json` |
| **预计改动** | ~120 行：对每实例取冻结 `EXACT013 INITIAL`，在 **FIT** 视角上计算当前相机的 Body 投影 IoU；同时枚举离散候选（绕环轴 0/90/180/270° × 法向翻转 ±）报告最优候选与差值 |
| **算法复用** | 复用 `native/geometry.project` 与冻结 Body；候选枚举是离散集合，不引入优化 |
| **是否改科学预测** | **默认否**：只写 `RING_AXIS_GAUGE_SUSPECT` 标记，不替换相机。若 RA 希望用它阻断 HERO/Body，则属"改流程"，需单独批准（见 R6） |
| **验证方式** | ① G03/005 必须报 `v0=0.304 / v1=0.842 / final=0.229`；② G02/005（0.556/0.554/0.550）与 G06/005（0.618/0.584/0.621）不得告警；③ 全部 78 个有相机视角重算 |

| **失败/回退** | 若离散候选的最优 IoU 与当前差异 <0.05，则该诊断无区分力，应停用并回到"只用 held 验证"；回退 = 删除输出文件 |

**重要约束：** 只能用 **FIT** 掩膜；**不得**用 HOLDOUT 或 GT；**不得**用被优化过的 B1 FINAL 作为选择依据（本轮已验证 INITIAL 与 FINAL 结论一致，故用 INITIAL 更干净）。

## 4. 不建议的两项（明确记录理由）

| 项 | 理由 |
|---|---|
| **R7 用 held-out 选择标定版本** | 会把验证集变成选择集；本报告 §Q2 已说明 `min(version)` 在 3/4 实例选错，但正确解法是"训练侧预注册规则"（BA 收敛 + 旋转离散 + FIT 投影一致性），不是用 held 挑版本 |
| **R8 放宽 Ring 3 px** | 78 视角中 77 已通过；唯一失败是真污染。放宽只多收 1 个坏视角，无收益 |

## 5. 执行顺序与门禁

```
1) R1 + R2（纯诊断）           —— 产出证据，不改预测；可在一个任务内完成
2) R4 + R5（纯标注）           —— 与前一步同批
3) R3（观测分支，默认关）       —— 独立任务；需要重新冻结输入 SHA
4) R6（实例级覆盖阈值）         —— 独立任务；必须 RA 批准具体阈值
5) 只有在 1–4 全部完成后，才讨论"是否需要改相机选择规则"
```

**每步的硬要求：**
- 输入、源码、参数先冻结（沿用 002 的 `TASK.yaml` 模式）；
- 预测先冻结，GT 后置；
- 每一步都必须能在**不重训**的前提下离线验证（R1/R2/R4/R5 天然满足；R3 需要重算相机，属新任务）。
