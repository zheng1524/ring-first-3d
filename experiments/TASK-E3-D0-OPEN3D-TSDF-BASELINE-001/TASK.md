# Step 1：HERO → Open3D TSDF 适配

## 1.1 直接使用成熟实现

首选：

`open3d.pipelines.integration.ScalableTSDFVolume`

使用官方：

- RGB-D 输入接口；
- TSDF 积分；
- `extract_triangle_mesh()`。

不要自行重写 TSDF 积分或 Marching Cubes。

## 1.2 数据适配

输入：

- 原始 HERO 深度；
- 对应 RGB；
- Polyp Mask；
- 原始 K/c2w；
- 已有 Ring CAD。

必须核对：

1. 原生 HERO 深度与归档工作分辨率的对应关系。
2. K 是否与实际输入深度分辨率一致。
3. 毫米和米的转换。
4. Open3D 所需 world-to-camera 外参方向。
5. 无效深度、背景、Ring 与 Polyp Mask 的处理。

**强制进行毫米尺度验证。**

例如，若将 HERO 深度从 mm 转成 m，则相机平移、TSDF 体素尺度和截断距离也必须统一为 m。输出模型再明确转换回 mm。

禁止直接使用 Open3D 室内场景教程中的体素尺度。

尤其注意：

**Mask 外部的未知区域不能被填成虚假的远距离深度，也不能把 Ring 或背景融合进息肉 TSDF。**

若标准 TSDF 在开放曲面边界生成异常封闭面，保留并报告，不静默修补。

## 1.3 单来源验证

选择：

`G01_004_ref08`

比较：

**原始 HERO Mesh → 单来源 Open3D TSDF Mesh**

检查：

- 主体位置是否一致；
- Ring 尺度是否一致；
- 表面是否发生明显收缩；
- 是否存在异常封闭；
- 是否丢失大量原始有效区域；
- 原始真实图像重投影是否合理。

不要求三角面数量一致，但必须证明单位、坐标、深度和输入适配没有明显错误。

如单来源即出现严重异常，必须先定位适配或 TSDF 表达问题，不能直接把异常归因于多视角融合。

**本阶段通过后冻结输入适配代码。**

# 四、重点：失败机制分析

**这部分是本轮最重要的科学任务。**

我预计标准 Open3D TSDF 可能出现以下问题：

| 潜在问题 | 重点分析的原因 |
|---|---|
| 大面积表面消失 | 有效域、观测权重、相机冲突或 TSDF 积分 |
| 表面异常封闭 | 标准 TSDF 与开放可见曲面的表达差异 |
| 细柄消失 | 体素分辨率、截断距离、观测覆盖不足 |
| 错误延伸被保留 | 原始 HERO 异常、缺少真实轮廓约束 |
| 多参考融合后形变 | 相机位姿与深度不一致 |
| G1 比 G0 更差 | 新增来源的相机或深度错误 |
| 局部出现重复面 | 观察冲突、零水平面提取或空间支持分裂 |

这些是**待检验假设，不是预设结论**。

必须结合真实结果判断。

尤其要区分：

**A：输入适配错误**

例如单位、外参、K、Mask 或深度格式错误。

**B：相机位姿问题**

例如新增来源整体出现系统性空间错位。

**C：HERO 深度与几何问题**

例如部分来源本身包含错误延伸或不合理曲面。

**D：TSDF 融合机制局限**

例如不同来源的冲突、开放表面边界问题、薄结构消失。

不要将所有错误笼统归因于 TSDF。

也不要把所有重复层都归因于单份 HERO。

分析应优先采用已有指标和真实重投影，避免增加复杂审查流程。

# 五、评价方式

必须使用相同世界坐标、相同视角、相同毫米尺度，对比：

**原始 HERO → G0 → G1**

重点报告：

1. 原始可信主体的保留情况。
2. 可见侧面是否增加。
3. 细柄和小型结构是否消失。
4. 多来源几何是否形成连续表面。
5. 错误延伸和异常连接是否仍然存在。
6. 真实目标 Mask 的覆盖与越界情况。
7. 与输入 HERO 的表面距离及连续性。

数值指标必须使用固定评价分母。

**不能只对输出 Mesh 尚存的部分计算误差，从而掩盖表面消失。**

也不能将 TSDF 自行生成的未知区域表面当作已认证的真实解剖结构。

可见观测区和 Unknown 必须区分。
