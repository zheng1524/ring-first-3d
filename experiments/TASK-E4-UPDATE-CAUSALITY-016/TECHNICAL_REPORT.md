# TECHNICAL_REPORT_SUMMARY

TASK-E4-UPDATE-CAUSALITY-016；分支 `exp/TASK-E4-UPDATE-CAUSALITY-016`；继承015提交 `905e2a9`。11个独立真实物理组，13条新真实更新、3条单一虚拟Ip场景控制。13条015输出是明确标识的只读对照，没有重新训练或冒充新结果。

## 核心答案

**错误更新有三条已分离的来源：轮廓最近边对应不保证三维同物点、候选/参数支持范围不完整、以及整向量更新把局部危险位移和其他可行位移捆绑。另发现G02粗分箱光栅化的前向片元状态不稳定。** 新提案机制改善了局部可行性和部分指标，但仍没有恢复可信长柄，不升级正式主线。

1. **不是缺少梯度就一定没有更新。** G03的42个远轮廓关联顶点中，旧四条局部候选带覆盖0；Stalk-C局部表达仅支持13，余29点的局部Jacobian严格为零。silhouette的有限光栅支持不会在远处缺失像素凭空生成顶点；最近轮廓距离把信号传给当前轮廓边，那里也未必是同一解剖部位。

2. **存在被整网格方向捆绑阻塞的可行下降。** G03全梯度0.2mm影子提案降低完整目标，却触发RING_WORSENING和RING_CONTAINMENT_WORSENING；固定接触面坐标后，仍降低完整目标 -0.00206744，完整Guard通过。最坏CAD见证点的主要内向贡献来自HERO绝对深度，而不是轮廓项。Ring门禁阻止局部危险位移是合理的；把其余顶点一起放弃则损失了可行方向。这里证明的是几何可行下降，不是有GT认证的正确形状。

3. **三角翼并非仅靠更新平滑就会消失。** 015-B优先把图像梯度应用到远轮廓关联带，全目标下降和无自交不约束它必须形成管状柄。新接触固定+Sobolev方案仍得到片状突出。G03的整个单视频候选池方向跨度也只有17.5449°，重新均衡不能生成缺失方向。逐顶点3×3的“满秩”不能代替耦合形变可辨识性，更不能认证最近边对应正确。

4. **G02加法异常已定位到粗分箱片元选择。** 同一前向图内加法约1e-7；复用片元后全梯度重复约2.7e-8；冻结Ring可见性或权重无效。相同顶点的默认粗分箱可在一个像素更换面ID、重选重心及距离，silhouette梯度重复相差 0.005309；官方bin_size=0降至 8.28e-08。受控CuBLAS工作区没有消除粗分箱现象，不能把它归因于一般矩阵乘或形状先验。015的FAIL保留；本轮真实更新仍沿用原后端，防止把数值后端修正混入采样/提案对照。
