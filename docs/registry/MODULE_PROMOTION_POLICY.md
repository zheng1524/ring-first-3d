# 共享模块晋升政策

技术注册表是正式工程定位入口；工程状态和科研状态分开维护。本轮用户明确授权最小共享包与实际测试，允许将 T01/T03/T04、T10–T13、T24 包装为 `HARNESS_VERIFIED_LIMITED`；T31/T34 为 `COMPATIBILITY_TESTED`。不改变旧模块的科研 CONDITIONAL/MIXED、失败路线与正式 baseline 状态。

新候选→登记原技术 ID/源码 commit/完整 SHA/输入输出→数学契约→真实 Smoke Test→独立评审→明确范围的共享接口。原代码采用 DIRECT_REUSE、AST_REUSE、ADAPTED_REUSE 或 REIMPLEMENTED 如实标注；禁止用新实现冒充原公式。接口变更必须说明坐标、单位、随机种子、FIT/HOLDOUT、无数据时的失败语义与恢复路径。

新研究任务先查注册表并调用现有接口；未满足的能力须说明差距。新增数学模型/损失需独立任务和契约，不通过接口封装暗中替换。先冻结参数和预测再评价；GT 不参与算法/结果选择，历史 S0/V2/直径/其他路线只能作为独立评价对照，不能补新预测。部署资产缺失保留 NaN/NOT_EVALUABLE，全体目标分母、独立成功、失败和配对比较不可缺失。

共享模块工程验收不授予新科学实验、路线改变或正式基线验收；这些决定继续由用户人工批准。完整优化器、HERO 推理/清理、联合 BA、九参数 Body 拟合、可视化发布仍需按各技术卡独立工程化，不能因本轮 Renderer PASS 宣称全部迁移。

Git 仅保存代码、配置、指标、报告、精选小图和资产索引；大型 Mesh/逐帧产物/原视频/权重/环境留 LOCAL_ONLY，固定路径、大小、SHA、来源、依赖和恢复方法。显式分支增量 push，提交前体积/来源检查。清理仅在用户授权范围内，以不可变清单、活动任务核查和已验证恢复证明为前提，不重写历史或删除失败证据。

main-ready 采用从 main 新建发布分支、逐文件添加文档和必要工程入口的方式。历史实验链接固定 commit，禁止以整体合并历史研究分支完成工程发布。源对象与真实资产是明确外部依赖；缺失时预检查失败，不提供模拟 PASS。详见 [Harness](../RESEARCH_EXECUTION_HARNESS.md)。
